HYPOTHESIS-ID: m5-status3-worker-dispatch

## Status at session start

s2007 reached shutdown calls 1, 2, and 3. Call 3 entered with
`D_80154620[0] == 0x01`, its first sampled `L_8009BD10` row was already
`status=0x00, a0=a1=1, v0=0`, and it returned. The existing worker census
still passed its positive control (24 phase-6 service entry/exit pairs), but
no status-3 row or PI assertion occurred. The next boundary is the writer and
transition provenance of the status-byte table, not shutdown reachability.

## Competing hypotheses

- **H-status3-never-written:** the port never writes `0x03` to the relevant
  status-table slot in the phase-gated recipe; the missing status-3 worker row
  is not evidence of scheduler starvation.
- **H-status3-transient-cleared:** the port writes a legitimate `0x03`, then a
  stop/reap path clears it before the first shutdown spin sample; writer order
  explains the zero row.
- **H-status3-other-slot:** the port writes `0x03` to another stride-
  `0x1228` voice slot while shutdown call 3 samples slot 0; the current
  single-byte sample is the wrong slot.
- **H-status3-uninstrumented-site:** a generated store site or address
  calculation is absent from the census; static enumeration and an exact
  destination/old/new probe will expose it.

## Discriminating measurement

One phase-gated table in one build/run must instrument every generated byte or
word store whose effective destination can be `D_80154620` (`0x80154620` plus
the `0x1228` slot stride), logging writer PC, effective guest address,
slot/index, old byte, new byte, phase, thread, and a run ordinal. Join those
rows to the existing s2007 shutdown entry/spin/exit rows and s2006
service/dispatch/return rows. The same run's shutdown calls 1–3 and the 24
service entry/exit pairs are positive controls; the retail oracle must again
show whole-RDRAM >=10,000 callbacks, a target-watch hit, and PC `0x8009B7EC`.

- A port `new=0x03` row for slot 0 before call 3, followed by a clear before
  the spin, selects H-status3-transient-cleared.
- A port `new=0x03` row only for another slot, while call 3 samples slot 0,
  selects H-status3-other-slot.
- No port `new=0x03` row with the positive controls live selects
  H-status3-never-written for this recipe; do not call it worker starvation.
- A static destination gap or a writer row with an unrecognized site keeps
  H-status3-uninstrumented-site live and requires fixing the census before a
  runtime conclusion.
