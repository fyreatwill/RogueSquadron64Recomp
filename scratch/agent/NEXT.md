# NEXT: who frees the audio list block 0x80179380 while the audio thread may still walk it (use-after-free?), and does retail quiesce audio first?
HYPOTHESIS-ID: m5-audio-destub
Established (s4560, 2/2 arms): after the mode flag word 0x800375A4 is reset to 0x40 by 0x800A9BD8 the guest rs_frees 0x80179380 (audio list nodes), 0x801714D0 (voice lattice) etc., reallocs 0x80179480 (73728) over them; ~750 log lines later musyxSynthFrame+5436 follows the stale link 0x000094FC (prev_node 0x80179510). The 833 flags=4 NULLs are a separate guest gate (mode flag bit 0x80), not shown to be related.
Hypotheses:
 H-quiesce-missing: guest sends a stop/flush to the audio thread and waits for an ack (event/message) the port's audio path does not honour, so the free races the audio thread. Port bug (M5).
 H-race-only: retail has no wait either; retail's audio task just does not run in that window. Port needs ordering (pause audio thread across guest frees).
 H-stale-head: guest legitimately resets the synth list head in a shutdown call (musyx stop) that the port stubs or skips, so the walker starts from a dangling head.
 H-not-uaf: audio thread is not live at the free; the stale link is written some other way (the timeline ordering is coincidence).
Discriminating measurement (one build, one run, both arms of the s4560 recipe): (1) in rs_free for ptr==0x80179380 and 0x801714D0 print a host backtrace_symbols (named guest functions) + vi; (2) count musyxSynthFrame entries with ms timestamps and log the last entry before the free and any entry between the free and the crash; (3) record every snd/audio/musyx-named guest function in the backtrace. Outcome map: shutdown function in the backtrace whose audio-thread effect is absent -> H-stale-head / H-quiesce (check what it waits on); no shutdown call and synth entries continue after the free -> H-race-only (then oracle: does retail's synth run after the same free); no synth entries between free and crash -> H-not-uaf.
Control: s4457-control=1 and [rs-nulldump-ctl] lines. Recipe scratch/agent/s4560_nulldump.sh (150 s, 2 arms).
