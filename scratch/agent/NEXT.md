# Does retail run musyxSynthFrame between shutdownAudioEngine and audio re-init?

HYPOTHESIS-ID: factor5-overlay-0x2c-splice

s4780: on the VI-640 phase-3 crash route the port runs shutdownAudioEngine (frees arena 0x801793F0.. at log 23457-23477), rs_malloc(73728)=0x80179480 reuses it, and musyxSynthFrame (still registered in VI slot 1) walks it ~215k log lines until the audio blocks are re-allocated (238132) - crash +5808. Hypotheses: A) retail also runs the synth in that gap but the freed memory is not repurposed because retail's heap hands out a different block (heap layout difference, port bug in allocator/ordering); B) retail does not run the synth in the gap (callback gated/stopped, e.g. VI callback not dispatched, or shutdown ordering differs: shutdownMusyXVoices/dereg runs first in retail); C) retail has the same gap and the same reuse but the synth tolerates it (list head cleared) - port-specific stale head pointer.
Discriminator (retail oracle, tools/oracle/README.md): execution watches on shutdownAudioEngine 0x80091D40 (phys 0x91D40), musyxSynthFrame 0x8009123C, shutdownMusyXVoices 0x8009BCC4, rs_malloc 0x80001ACC; order them in time around the VI-640 scene transition. Control: whole-RDRAM watch must fire ~1.6M in 8 s, and shutdownAudioEngine must fire at least once or the route is unqualified. A => synth fires after shutdown and before re-init, and the 73728 alloc lands elsewhere; B => no synth entry between shutdown and re-init; C => synth fires, alloc same address.
